## What I learned

> [!normative]
> When the Obsidian vault root is the repo root, EVERY committed folder participates in the file explorer — including code dirs (`chio-pack/`, `kb-engine/`, `infra/`) that aren't notes. Obsidian renders them harmlessly but the noise is real and can't be hidden via committed config.

The vault-root-vs-repo-root question (resolved by [[../../decisions/ADR-0003-vault-layout|ADR-0003]]) revealed an ergonomics tension I hadn't anticipated: making everything wikilinkable also means everything appears in the file explorer. The fix is per-user (Obsidian's "Excluded files" setting in `app.json`, gitignored), so the canonical state ships with code folders visible.

A fully clean answer would either spread `vault/` contents at repo root (huge refactor touching every reference) or rename `vault/` to `kb/` and accept it. Both deferred to a future ADR. ADR-0003 explicitly notes this as a "negative consequence" so future-me can find the trade-off when deciding whether to revisit.

> [!receipt]
> Hand-seeding episodes with the same shape as `migrate-seeds.py` produces means the first migrate-seeds run is a quiet overwrite, not an "adding seven new episodes" event. That's the difference between idempotent and additive — both technically correct, but only one feels right when you re-run a script.
